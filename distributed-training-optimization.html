你會發現，多數人講分散式訓練，講的都是「技術點」：DDP、FSDP、ZeRO、Mixed Precision、Gradient Checkpoint… 但工程師真正缺的是 架構思維：何時用什麼？怎麼組合？瓶頸在哪？這篇就是回答這些問題。

The Core Idea
優化的核心是：先找到瓶頸，再用對應手段解決，而不是盲目疊加技術。

01北極星目標

所有設計決策的起點，是先把目標說清楚。在分散式訓練裡，北極星目標只有兩個：

🎯 Two Goals
  • 最大化吞吐（throughput）：samples/sec 或 tokens/sec
  • 顯存約束內訓練穩定收斂：放得下、跑得穩、不 OOM、不 NaN

所有後面的優化手段，都是這兩個目標下的權衡（trade-off），沒有銀彈。

02三大資源視角

我喜歡把所有優化都映射到三個資源軸上 —— 這是面試裡最容易拿分的「結構化思維」：

💾

Memory（顯存）

放得下嗎？模型權重 + 梯度 + 優化器狀態 + activation。

🔗

Communication（通訊）

傳得快嗎？AllReduce / AllGather / ReduceScatter。

⚡

Compute（算力）

算得滿嗎？GPU 利用率、kernel 效率、算術強度。

💡 統一原則

每一個優化手段都在「動」這三個資源中的至少一個。當你看到一個新技術，先問：它降的是哪個？換的是哪個？

選並行策略（結構層）

讓通訊隱藏在計算裡：async NCCL、backward overlap、prefetch all-gather、pipeline overlap (L / L-1 / L+1)。

5

Fused kernel、Fused optimizer、合理 batch（提高算術強度 arithmetic intensity）、CUDA Graphs（減少 launch overhead）。

3.1 減少通訊量（Compression）🔥

(1) Quantization 量化

FP32 → FP16 / 8-bit / 4-bit / 1-bit。最常見、最容易拿到收益的手段，bf16 幾乎是現代 LLM 訓練的標配。

(2) Sparsification 稀疏化

只傳 top-K 梯度（例如前 1%），其餘清零。在頻寬極差的環境（跨機房）有效。

(3) Threshold-based

只傳超過某個閾值的梯度，動態調整稀疏率。

(4) Sign-based（極端壓縮）

只傳梯度符號（+/-）。代表方法：SignSGD。32× 壓縮率，但需要精心設計才能收斂。

(5) Error Feedback（一定要寫！）

⚠️ 為什麼是必選

壓縮會丟資訊。如果不補回來 → 訓練會發散（diverge）。Error Feedback 把這次「壓縮損失的部分」存起來，下次補回去。

# Pseudocode: Top-K with Error Feedback
error = 0
for step in training:
    g = compute_gradient()
    g_corrected = g + error            # 補上次的殘差
    g_compressed = top_k(g_corrected)  # 壓縮
    error = g_corrected - g_compressed # 記錄這次的殘差
    all_reduce(g_compressed)
    update(g_compressed)

(6) Low-rank Compression（進階）

把梯度矩陣做低秩分解 G ≈ U·Vᵀ，只傳 U, V。PowerSGD 是經典代表。

3.2 減少通訊次數（Frequency）

  • Bucket Fusion：把多個小 tensor 合併成一個 bucket 再 AllReduce，減少啟動成本（latency）。
  • Gradient Accumulation：累積 N 個 micro-batch 的梯度後才同步一次，等效擴大 batch。

3.3 提高頻寬利用（Bandwidth）

  • Bucket size：太小 → latency dominated；太大 → overlap 不到。10–50MB 是常見起點。
  • Topology-aware：NCCL 自動偵測 NVLink / PCIe / IB，挑最佳 ring/tree 拓撲。

3.4 隱藏通訊時間（Overlap）

這是最重要的一節。看一張 timeline：

┌── Layer L ──────────────────────────────────┐ │ Forward ▓▓▓▓ │ │ Backward ▓▓▓▓▓▓ │ │ AllReduce ░░░░░░░░ ← 串行：浪費！ │ └──────────────────────────────────────────────┘ vs. ✅ Overlap ┌── Layer L ──────────────────────────────────┐ │ Backward L ▓▓▓▓▓▓ │ │ AllReduce L ░░░░░░░░ ← 同時進行 │ │ Backward L-1 ▓▓▓▓▓▓ │ │ AllReduce L-1 ░░░░░░░░ │ └──────────────────────────────────────────────┘

三個重要 overlap 技術：

  1. Backward overlap：當前 layer 算 backward 時，上一個 layer 的 gradient 已經在 reduce-scatter。
  2. Prefetch：FSDP 在算 layer L 時，提前 all-gather layer L+1 的權重。
  3. Pipeline overlap：1F1B / interleaved schedule，讓不同 micro-batch 的 forward / backward / comm 並行。

互動式決策樹（點擊展開）

🟢 GPU 利用率 > 90%、NCCL 佔比低 → 我是哪一類？ ▼
你是 Compute-bound。優化方向：fused kernels（FlashAttention、Apex fused optimizer）、bf16、提高 batch size 增加算術強度、CUDA Graphs。
🟡 NCCL 時間長、GPU 經常等通訊 → 我是哪一類？ ▼
你是 Communication-bound。優化方向：bucket fusion、backward / prefetch overlap、compression（量化或 top-K）、檢查網路拓撲（NVLink / IB）。
🔴 GPU 利用率低（< 70%）、波動大 → 我是哪一類？ ▼
你是 Input-bound（DataLoader 餵不上）。優化方向：增加 num_workers、pin_memory、prefetch_factor、用更快的格式（webdataset / arrow）、考慮 GPU 解碼。
💥 OOM、batch 上不去 → 我是哪一類？ ▼
你是 Memory-bound。優化順序：bf16 → activation checkpoint → FSDP/ZeRO-3 → CPU/NVMe offload。盡量先用前面便宜的手段。

05關鍵組件如何組合（實戰模板）

三套模板 cover 95% 場景。先選符合你規模的模板，再按決策樹微調：

適用場景

單機 8×A100 / H100，模型 < 7B 參數，研究實驗、微調、原型開發。

組合

  • 並行：DDP
  • 精度：bf16 Mixed Precision
  • 通訊：Default Gradient Bucket（25MB）
import torch
from torch.nn.parallel import DistributedDataParallel as DDP
from torch.cuda.amp import autocast, GradScaler

model = MyModel().cuda()
model = DDP(model, bucket_cap_mb=25, gradient_as_bucket_view=True)

scaler = GradScaler()
for batch in loader:
    optimizer.zero_grad(set_to_none=True)
    with autocast(dtype=torch.bfloat16):
        loss = model(batch)
    scaler.scale(loss).backward()
    scaler.step(optimizer)
    scaler.update()

適用場景

單機顯存放不下 + 多機 (2~8 nodes)，模型 7B–70B，常見的 LLM finetune / 預訓練中等規模。

組合

  • 並行：FSDP（FULL_SHARD）
  • 精度：bf16 + reduce-scatter in bf16
  • 顯存：Activation Checkpoint
  • 通訊：Bucket + Prefetch + Backward Overlap
from torch.distributed.fsdp import (
    FullyShardedDataParallel as FSDP,
    ShardingStrategy, MixedPrecision, BackwardPrefetch,
)
from torch.distributed.fsdp.wrap import transformer_auto_wrap_policy
from torch.distributed.algorithms._checkpoint.checkpoint_wrapper import (
    checkpoint_wrapper, CheckpointImpl,
)

mp_policy = MixedPrecision(
    param_dtype=torch.bfloat16,
    reduce_dtype=torch.bfloat16,
    buffer_dtype=torch.bfloat16,
)

model = FSDP(
    model,
    sharding_strategy=ShardingStrategy.FULL_SHARD,
    mixed_precision=mp_policy,
    backward_prefetch=BackwardPrefetch.BACKWARD_PRE,  # 關鍵：overlap
    auto_wrap_policy=transformer_auto_wrap_policy,
    forward_prefetch=True,
    limit_all_gathers=True,
)

# 對 transformer block 加 activation checkpoint
apply_activation_checkpointing(
    model,
    checkpoint_wrapper_fn=lambda m: checkpoint_wrapper(m, checkpoint_impl=CheckpointImpl.NO_REENTRANT),
    check_fn=lambda m: isinstance(m, TransformerBlock),
)

適用場景

數百張卡 / 多機房，模型 > 100B，預訓練大型 LLM。

組合（3D Parallelism）

  • 並行：FSDP / DP × TP × PP
  • 精度：bf16（避免 fp16 溢出）
  • 顯存：Selective Activation Checkpoint
  • 通訊：Aggressive overlap (1F1B / interleaved)
  • 算子：FlashAttention-2 / Fused RMSNorm / Fused SwiGLU
# 概念示意（實際多用 Megatron-LM / DeepSpeed / TorchTitan）
parallel_config = {
    "data_parallel":    8,    # DP
    "tensor_parallel":  8,    # TP, 通常 = NVLink 域大小
    "pipeline_parallel": 4,   # PP, 跨機房
    "schedule": "1F1B-interleaved",
}
# 訣竅：TP 放在機內（NVLink），DP/PP 放在機間（IB）
# 因為 TP 通訊量最大（每層都要 AllReduce activation）
💡 拓撲匹配原則

把通訊量最大的並行軸放在頻寬最高的網路上：TP → NVLink > DP → IB > PP → 跨機房。

06關鍵參數調優

真正讓 training 快起來的，往往不是換技術，而是這幾個 knob 調對了：

參數取值範圍影響怎麼調
bucket_size_mb 10 – 50 MB overlap 粒度 vs 通訊效率 NCCL 時間長 → 調大；overlap 沒蓋住 → 調小
activation_checkpoint Per-layer / Selective 顯存↓ vs 計算 +30% OOM 才開；只 checkpoint attention/MLP
micro_batch_size 1 – 8 算術強度 / pipeline bubble 大模型先小再增；觀察 GPU util
gradient_accumulation 1 – 64 等效 batch / 通訊頻率 頻寬差 → 調大；要 throughput → 平衡
forward_prefetch True / False 顯存↑ vs overlap↑ 顯存有空間 → 開
num_workers (DataLoader) 4 – 16 I/O bottleneck GPU util < 70% → 調大
⚠️ 調參要點

每次只調一個 knob、用 profiler（torch.profiler / Nsight）看 timeline、保留 baseline 對比。絕對不要同時改三個東西然後猜哪個有效。

07一個統一抽象（很加分）

如果讓我用一句話總結所有優化技術 —— 它們其實只在做三件事：

📦

① 減少數據量

compression / lower precision / sparsification

🔁

② 減少次數

bucket fusion / gradient accumulation

👁️

③ 隱藏時間

overlap / pipeline / prefetch

Interview-Ready One-Liner
Efficient distributed training is achieved by systematically optimizing
memory usage, communication overhead, and compute utilization
based on the observed bottleneck.

TL;DR

  1. 北極星：throughput + 穩定收斂。
  2. 三大資源：Memory / Communication / Compute —— 所有技術都在動這三個軸。
  3. 5 步流程：選並行 → 放得下 → 傳得快 → 傳不被看到 → 算得快。
  4. 決策樹：先 profile，找到瓶頸（OOM / Comm / Compute / I/O），再對症下藥。
  5. 三套模板：DDP（小）→ FSDP+AC（中）→ 3D Parallelism + Fused kernel（超大）。
  6. 核心心法：先找瓶頸，再用對應手段，不要盲目疊加技術。
